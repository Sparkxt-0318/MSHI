# Verification of the second round of fixes (2026-11-02)

Third check of the v3 package, run after commit `a6c00bc` (which fixed the 20 findings in `fix_verification.md`). Four reviewers each took one area: `chain` (provenance chain and reproduction gate); `modis-rasters` (MODIS stage and raster fetches); `repro-guards-docs` (reproduction table, guards and documentation); `end-to-end` (the whole pipeline end to end on stand-ins for the blocked sources). None changes a reproduced number. All are fixed in the commit that adds this file; the fix for each is given below.

### 2.1 chain-fresh-clone-gitignored-outputs-stale (chain): Fresh clone: results whose recorded outputs are gitignored read as STALE, so `make data`/`make repro` exit 2 and `make test` then fails

Finder's severity: medium. Verifier: **confirmed**, low. Location: `mshi/io.py` 210-213 (also mshi/analysis/repro_checks.py:121-123, 182-186, 209-211).

result_staleness reports a recorded output that is absent as 'missing its output', which makes the result STALE. modis_points.json records data/interim/modis_points.parquet and features.json records the feature tables. fetch_worldclim.json and fetch_soilgrids.json record rasters under data/raw. All of these paths are gitignored (.gitignore: data/raw/, data/interim/; D-P1-12). Once the results of a networked `make all` are committed (the planned next step, Q-1), every fresh clone has these results but not their outputs. repro_checks, run by `make repro` or as the last stage of `make data`, then marks both NPP rows STALE ('modis_points.json missing its output data/interim/modis_points.parquet; re-run `make all`'). It raises StaleInputError (status stale, exit 2), rewrites the committed table and closes the reproduction gate. Afterwards test_reproduction_table_has_no_fail fails and test_npp_correlation is skipped. Nothing is actually stale: config, code and committed values all match the checkout. In a container like this one, where Planetary Computer is blocked, the state can never be cleared. Before a6c00bc the same state gave NOT RUN. Note that the skip message of test_fresh_rebuild_matches_committed_tables tells users to run `make data` first.
